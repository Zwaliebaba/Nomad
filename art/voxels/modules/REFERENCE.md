# Station screenshot modules

The 24 `reference_*.vox` files reconstruct the distinct module types in the owner's
2026-11-07 isometric station screenshot. Repeated structures share a file; the
three tower silhouettes, two solar-array sizes, three platform sizes and four
bridge junctions have separate files. Ships, asteroids and the starfield are not
base modules and are excluded.

These are visual reference assets. Hidden walls, undersides and interior details
are inferred, and descriptive names do not assign new gameplay rules. Existing
module files are preserved. The assets are registered in `set.json`, and their
game-readable JSON is generated by `nomad-vox` (D-289). They are not automatically
placed into the current station scene or assigned to gameplay slots.

## Editing and coordinates

Open any file in MagicaVoxel 0.99.6 or later. Files use format 200, a named scene
object and a shared 21-colour palette. Cyan lights, white emitters, amber energy
and red beacons have Emit materials. Greenhouse glazing is an open lattice with
visible planting; it does not rely on alpha transparency, which the game importer
ignores.

`+z` is up; footprints are centred about x/y, with the ground plane at z=0.
The hangar opens towards `+x`. Dimensions follow the reference's visual proportions
rather than the existing gameplay slot sizes. `reference_inventory.json` records
each file's bounds, voxel count and interpretation. Empty enclosed volume is
omitted; all exposed surfaces, including undersides and internal openings, remain
editable voxels. Holographic ring marks are separate luminous voxels by design.

After editing, run from the repository root:

```bash
cargo run --locked -p nomad-vox -- import
cargo run --locked -p nomad-vox -- import --check
cargo test --locked -p nomad-vox
```

Keep the `.vox` sources and regenerated JSON together. The existing reference
modules do not replace the original gameplay models.
